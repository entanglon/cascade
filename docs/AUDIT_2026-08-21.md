# Cascade — Full Codebase Audit (2026-08-21)

> Scope: architecture, security, reliability, concurrency, performance, ops.
> Method: full-source sweeps (31,301 LOC across App/Engine/Storage/Telegram/Crypto/Features),
> targeted deep reads of every critical mechanism, live-verification of DB/channel state,
> and external research (OWASP 2026 password-storage guidance, TDLib upstream issues,
> Telegram platform limits). Zero-cost improvements only.

---

## 1. Executive summary

The architecture is fundamentally sound: chunked encrypted storage over Telegram with a
local SQLite catalog, dual-channel redundancy (vault + immutable backup mirror), tombstone-
based deletion, byte-perfect byte-range streaming into mpv, and layered defenses that were
individually verified this session (deletion absolutism, read-ahead streaming, flood-wait
hardening). The crypto core follows current OWASP guidance where it matters most.

The weaknesses are concentrated in three themes:

1. **Silent failure surface** — ~430 `try?` and 66 bare `catch {}` blocks vs only 4
   user-facing error notifications. Most failures are invisible.
2. **Local-auth strength** — the vault PIN is verified against an *unsalted* SHA-256 hex
   hash with a non-constant-time compare. Everything else in the crypto stack is strong;
   this is the weak link at the door.
3. **Operational drift** — CI targets Xcode 15.4/macOS-14 runners that cannot build this
   Swift 6.3 / macOS 26.5 project; docs reference pre-rename paths; LogManager exists but
   receives only test entries while real diagnostics go to ad-hoc `/tmp` files.

None of these are catastrophic; all are fixable for free.

## 3. Findings

### HIGH

**H1. Vault PIN verification is unsalted fast SHA-256**
`KeychainStore.verifyVaultPIN` (KeychainStore.swift:130-133) compares
`sha256hex(pin)` to a stored hex string. If the Keychain item is ever exfiltrated
(laptop compromise, backup migration), a 6-digit PIN falls to instant brute force.
Also uses `==` (non-constant-time).
*Fix*: store PBKDF2-HMAC-SHA256(600k) + random 16-B salt (same primitive already in
CryptoEngine); compare digests constant-time (`timingSafeEqualBytes` loop); add a small
attempt-delay ladder (e.g., 2^n seconds after n failures).

**H2. Silent-failure surface (~430 `try?`, 66 bare catches, 4 user notifications)**
Data-mutating operations can fail invisibly: caption syncs, thumbnail sidecars, share
revokes, cache evictions. The banner system exists (item 10) but reaches almost nothing.
*Fix*: triage the ~20 highest-stakes call sites (anything writing to Telegram or deleting
rows) and route failures through `notify(...)`/LogManager. Mechanical, incremental.

**H3. CI cannot build this project**
`.github/workflows/ci.yml` pins `macos-14` + Xcode 15.4 fallback; the app needs the
macOS 26.5 SDK / Swift 6.3 toolchain. Every CI run fails or tests nothing. Also note:
private-repo macOS minutes bill at 10× (free tier ≈ 200 macOS-minutes/month).
*Fix*: bump runner image (`macos-26`) + drop the Xcode 15.4 fallback line; keep the job
to Debug-build only (~5–8 min/run) so it fits the free tier; run the test suite locally
via the existing script before pushes.

### MEDIUM

**M1. Share-link password KDF below current bar** — `deriveLinkKey` uses PBKDF2 100k
(CryptoEngine.swift:218). OWASP's 2026 floor for PBKDF2-SHA256 is 600k. Raise it (new
links only; old links keep working via their recorded params).

**M2. Keychain accessibility too broad for long-lived secrets** — items are saved
`kSecAttrAccessibleWhenUnlocked` (KeychainStore.swift:33) which allows migration to other
devices via iCloud Keychain backup flows. Master key and PIN hash should be
`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`. Migration: re-save existing items once on
launch (read → delete → add with new attribute).

**M3. AppState is a god object** — 2,559 lines spanning uploads, navigation, shares,
trash, sync scheduling, notifications, debug hooks. Highest-value extraction:
(a) `UploadManager` (queue/drain/perform/pause/resume, ~400 lines),
(b) `ShareCoordinator`, (c) `CatalogSyncScheduler`. Each removal shrinks MainActor
contention and makes testing tractable.

**M4. View-layer monoliths** — FileBrowserView.swift (3,459 lines), MPVVideoView.swift
(2,632), TheaterView.swift (1,782). The type-checker complexity limit has bitten here
before (documented in HANDOVER §6). Split incrementally when next touched; don't big-bang.

**M5. No crash/hang memory across launches** — bootLog (item 146) proves how far a launch
got, but nothing tells the *user* "last launch crashed". Cheap detector: write a heartbeat
file at bootstrap end; on next launch, if heartbeat exists without a clean-exit marker,
show a one-time "previous launch didn't finish" banner. Free, ~30 lines.

**M6. Rate limiter UX under bulk ops** — sustained 20 writes/min means deleting a
100-message batch takes ≥5 min of pacing. Correct for ban-safety, but the UI should say
so ("Telegram rate limit — finishing safely…") instead of looking stalled. Surface
RateLimiter waits through the existing banner/transfer text.

### LOW

**L1.** `verifyVaultPIN` string `==` — timing side channel; subsumed by H1's rewrite.
**L2.** Legacy `recoveryKey` (150k, fixed salt) — intentionally frozen for legacy blob
migration; document an expiry date and delete the path after.
**L3.** LogManager idle — real engine events go to `/tmp/cascade-*.log` ad-hoc files;
route stream/delete/upload events through LogManager so diagnostics survive reboots in
one place.
**L4.** Docs drift — several HANDOVER sections still reference xCloud-era paths/names.
**L5.** Strict-concurrency is partial — `nonisolated(unsafe)` is concentrated in
TelegramClient tracking dicts (NSLock-guarded, acceptable) but the module isn't built
with Complete checking; enable per-file as refactors touch them.

## 4. External research notes

- **OWASP Password Storage (2026)**: Argon2id `m=19456,t=2,p=1` is the preferred default;
  PBKDF2-HMAC-SHA256 600k remains the accepted FIPS-path minimum — our vault KDF matches;
  our PIN path does not (H1). CommonCrypto has no Argon2id; adding it means a third-party
  package (free, but supply-chain weight) — optional later.
- **TDLib upstream (maintainer responses in tdlib/td #225/#1546/#2971)**: the whole
  database directory must persist and must never be copied while running; sessions stay
  valid indefinitely if state persists. Cascade already complies (tdlib dir untouched by
  backups; resetVault recreates cleanly).
- **Telegram-as-storage risk model**: ToS was not designed for mass storage; realistic
  risks are report-based moderation and undocumented throttling, not automatic size-based
  bans. Mitigations already in place: encryption (content invisible), private channels
  (invisible unless linked), moderate request pacing, no public advertising of channels.
  Residual risk is account-level and unavoidable — the backup mirror + local export
  (ExportEngine) are the correct hedges. Consider surfacing "export your vault locally"
  more prominently in Settings as disaster insurance.
